## 2. Диагностика этапа 3.2

Журнал 3.2 сохранил статус «в ответе нет JSON-объекта» и не сохранил сырой текст пересмотра. Поэтому одна причина того ответа не объявляется доказанной. По коду и размерам видно следующее.

| Наблюдение | Статус |
| --- | --- |
| Ollama 0.40.9 выбирает режим JSON Schema: порог в коде — версия 0.5. В отчёте 3.2 режим не записывался. | Не доказано, что сервер отверг схему. Скрытый повтор с `format=json` существовал и не входил в счётчик вызовов. |
| Полный JSON пересмотра при полях до 300 символов занимает 3207 символов. При 6 символах на токен это уже больше 512. | Потолок 512 мал для полного ответа. Это не доказывает, что живой текст 3.2 был оборван: у оборванного JSON обычно остаётся открывающая скобка, а ошибка была «нет JSON-объекта». |
| Запрос пересмотра тогда занимал около 3741 символа пользователя и 621 символ системного текста при `num_ctx` 2048. | Давление на контекст возможно. Переполнения по сохранённому журналу не видно. |
| Оба ремонта ушли на первую формулу: сначала не было корня `sigmoid`, затем родитель не был пустым. На пересмотр ремонта не осталось. | Это подтверждено отчётом 3.2 и кодом бюджета. |

В живом прогоне 3.3 сервер принял схему на всех пяти ответах. Перехода на `format=json` не было. Признака обрыва `done_reason=length` не было.

## 3. Бюджет

Верхние границы прежние: 6 обращений к генерации, 1 план, 2 ремонта, 2 пересмотра, 3 формулы на оценке.

Фактический запрос `/api/chat`, включая повтор при отказе схемы и повтор HTTP, прибавляется к счётчику. Если на повтор схемы не остаётся места в шестёрке, повтор не отправляется, причина записывается.

После того как первая формула уже исполнена, последний свободный ремонт не тратится на неё ещё раз: он остаётся пересмотру. Пока исполнимой формулы нет, начальная гипотеза по-прежнему может занять оба ремонта.

Техническое поле `parent_hypothesis_id` у первой гипотезы, если формула уже допустима, приводится к `null` без вызова модели. Выражение при этом не меняется. Добавление `sigmoid` по-прежнему записывается как смена отображения в вероятность и не считается эквивалентной заменой.

## 4. Проверка JSON

Схема уходит в поле `format`, когда версия Ollama не ниже 0.5. Python после этого отдельно проверяет поля, AST, горизонт, признаки, родителя и закрытые периоды. В попытке хранятся `schema_mode`, `format_fallback`, `fallback_reason`, `truncated` и `generation_requests`.

Запрос пересмотра стал короче. В нём остаются план, формула родителя, его id, числа Desk, причина неудачи, список операций и запрет менять горизонт, оценку и закрытые периоды. Длинный текст памяти в этот запрос больше не кладётся.

## 5. Смысл формулы

`sign(momentum_7)` и `sigmoid(sign(momentum_7))` разбираются как разная структура. Вторая не считается доказанно равной первой. Коммутативная перестановка сложения, которую уже умеет анализатор, считается повтором и заново не считается. Только смена коэффициентов отклоняется до оценки. Родительская строка не переписывается.

На этапе 3.2 до оценки дошла одна формула, оба пересмотра остались текстом без JSON. На этапе 3.3 первый пересмотр вернулся JSON в режиме схемы и был сравнён с родителем на тех же датах. Он не стал лучше. Второй пересмотр не открыл новую формулу: анализатор увидел ту же сумму.

## 9. Что остаётся

Один прогон не измеряет частоту удачных черновиков. Первая формула снова пришла без корня `sigmoid`. Анализатор не доказывает алгебраическую эквивалентность за пределами уже существующего скелета сложения и умножения. Независимой проверки на закрытых годах нет. Торговли нет.
