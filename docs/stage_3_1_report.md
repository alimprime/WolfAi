## 1. Исправление Semantic Validation

На этапе 3.0 черновик `HYP-2024-SYNTH-001` получил `time_boundary` только потому, что год стоял в техническом идентификаторе.

Проверка разделена на три слоя:

- `hypothesis_id` — метка. Календарный год в ней не выбирает рыночный ряд.
- `description` — текст. Он не разбирается как формула и не открывает даты.
- `expression`, а также `test_plan`, `rationale` и `limitations` — здесь ссылка на закрытый период, на `holdout`, на `y_up`, `future_return` или просьба подобрать коэффициенты по 2021 году по-прежнему отклоняется.

JSON-схема, AST, список признаков, глубина и число узлов сохранены. Регрессия `HYP-2024-SYNTH-001` с годом в идентификаторе и в описании проходит проверку и считается на заранее заданном окне.

## 2. Схема цикла

Один проход `run_improvement_loop`, по умолчанию dry-run:

1. Генерация одной гипотезы `QwenResearchBrain`.
2. Проверка JSON и математики отдельно от модели.
3. Проверка происхождения точек: метка доступна позже решения, дата не позже 2021 года.
4. Проверка дубликата по выражению, признакам и горизонту.
5. Счёт на фиксированном разрезе. Модель этот разрез не выбирает.
6. Сравнение с константой 0.5, с частотой уже созревших исходов и с логистикой, обученной только на 2019 годе.
7. Короткий JSON обратной связи из двенадцати полей. SQL, ряд и закрытая выборка в него не входят.
8. До двух пересмотров. Новая версия получает свой id и `parent_hypothesis_id`. Прежняя строка не переписывается.

Потолок цикла: 1 начальная гипотеза, 2 пересмотра, 3 уникальных выражения, один клиент Qwen, без фонового процесса и без бесконечного повтора. Пороги Brier, log loss, зазора и минимума 60 наблюдений между попытками не меняются. Автор не ставит себе оценку: её пишет `verification-desk`.

| Зазор | не меньше горизонта; на горизонте 3 дня зазор 183 дня |

## 3. Живой цикл Qwen

Один dry-run `qwen3.5:4b`, digest `d8b0f5e9760cd1682034f292d7ef72ec46f432149be0df7574bf2d6e92e38c04`, Ollama 0.40.9. Журнал и Research Memory не записывались. Три вызова, 51.82 с. Клиент держал около 48 МБ. До первого вызова свободно было 4.46 ГиБ. После цикла `ollama ps` пуст.

| Попытка | Результат |
| --- | --- |
| 1. Генерация | `HYP-2024-SIGMOID-MOM`, выражение `sigmoid(momentum_7 * 2 + volatility_30 * -1)`, горизонт 3 дня. Год в идентификаторе проверку не остановил. |
| 2. Пересмотр | Отклонён: корень выражения не `sigmoid`. Счёта нет. |
| 3. Пересмотр | Та же причина. Счёта нет. |

Внутренний счёт первой формулы, 60 точек, зазор 183 дня:

| Метрика | Значение |
| --- | --- |
| Brier формулы | 0.25375 |
| Log loss | 0.701441 |
| Brier константы 0.5 | 0.25000 |
| Brier прошлой частоты | 0.252202 |
| Brier логистики 2019 | 0.253627 |
| Улучшение против 0.5 | −0.00375 |
| Интервал улучшения | −0.045008 … 0.037507 |

Точечная оценка хуже константы 0.5. Интервал содержит ноль, поэтому отличие совместимо со случайным колебанием. Оба пересмотра не дошли до счёта, сравнивать их с исходной формулой нельзя. Пересмотренная версия не стала лучше. Это не прогноз BTC и не закономерность.

## 5. Ограничения

Цикл не обучает веса Qwen. Память копит формулы и метрики, а не меняет модель. Слабая формула не удаляется, но и не объявляется законом. Если свободной памяти меньше 4 ГиБ до первого вызова, цикл останавливается. Между вызовами одной и той же модели допускается короткое ожидание её выгрузки, не запуск второй копии.

Живые пересмотры в этом прогоне не дали пригодной формулы. Следующий этап может сузить подсказку модели, чтобы пересмотр сохранял корень `sigmoid`, и только потом снова сравнивать версии на том же фиксированном окне.
