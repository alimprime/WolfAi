# Архитектура после Data Foundation

Phase 1 оставляет рабочими `Candle`, `load_candles`, `validate_candles` и `HistoricalQuantileBaseline`. Ниже — границы модулей, которые появятся дальше. Классов агента, новостного сборщика и проверки формул в коде пока нет.

## Инвариант времени

У каждого внешнего наблюдения хранятся:

| Поле | Смысл |
| --- | --- |
| `event_time` | Когда событие произошло |
| `published_at` | Когда источник сделал его публичным |
| `ingested_at` | Когда запись попала в локальное хранилище WolfAi |
| `source` | Имя источника |
| `source_version` | Checksum или иная неизменяемая версия выгрузки |
| `confidence` | Достоверность от 0 до 1 |

Решение в момент `t` видит запись только при `published_at <= t`. Сравнение идёт по абсолютному времени, с часовым поясом. `event_time` и `ingested_at` границу не заменяют: поздняя загрузка старого архива не прячет его из истории, а ревизия с более поздним `published_at` в ранний тест не входит. Ревизия хранится отдельной записью, прежняя строка не переписывается.

Дневная свеча Binance помечена временем открытия, `00:00 UTC`. Её close известен в `00:00 UTC` следующих суток. Это время возвращает `daily_bar_available_at`, и `Forecast.as_of` теперь равен ему. Горизонт отсчитывается от последнего известного close. Новости, кошельки и макроряды отсекаются по `published_at <= as_of`.

Макропоказатель привязывается ко времени официального релиза. Индекс потребительских цен за декабрь, опубликованный в январе, в декабрьский тест не входит. Ряды 2008 года остаются контекстом традиционных рынков и не смешиваются с историей BTC.

Пропуски свечей не заполняются выдуманной ценой.

## Модули

`wolfai.data` читает и проверяет OHLCV. Внешние ряды живут в `wolfai.intelligence`: общая запись `Observation`, видимость по точному `published_at`, поиск аналогов и ablation. Источники, лицензии и то, что не вошло в строгий тест, описаны в [INTELLIGENCE.md](INTELLIGENCE.md).

### MarketDataEngine

Исторические цены и объёмы. Вход: локальный ZIP Binance Vision и его checksum. Выход: `list[Candle]`, нормализованный CSV и manifest (`source`, `source_version`, время загрузки, число строк, первая и последняя метки). Сеть внутри исследовательского цикла не используется: скачивание делает отдельный шаг до импорта. Дыры в календаре останавливают импорт.

### WhaleIntelligence

Крупные держатели BTC и биржевые потоки. Вход: on-chain события с `DataProvenance`, где `event_time` — время блока, а `published_at` — момент, когда наблюдение стало публичным. Выход: изменения баланса и потоки с `confidence`. Перевод между кошельками не помечается как покупка или продажа. Приватные ключи и API торговых аккаунтов не читаются.

### MarketIntelligence

Новости, ETF и макроэкономика. Вход: сообщения и релизы с теми же шестью полями происхождения. Выход: нормализованные события за выбранное окно. В тест попадают только публикации к моменту решения.

### HistoricalMemory

Поиск похожих прошлых окон по числам: доходность, волатильность, просадка, режим объёма. Вход: вектор, посчитанный Python по данным с `published_at <= t`. Выход: окна, которые целиком закончились не позже `t`, оценка сходства и то, что случилось после них. Исход аналога известен потому, что аналог уже в прошлом; в признаки текущего окна он не копируется. Память не хранится в свободном тексте модели.

### MathematicalEngine

Проверка уравнений, которые предложила Qwen. Формула приходит структурой, а не произвольным Python. Допустимы арифметика, `abs`, `log`, `min`, `max` и обращения к полям свечи с лагом `<= 0` (`close[0]`, `close[-1]`, `volume[-5]`). Положительный лаг, вызов произвольной функции и чтение данных после `t` формулу бракуют. Движок считает ошибку на walk-forward и сравнивает её с `HistoricalQuantileBaseline`. Деление на ноль, нечисловой результат и противоречие OHLC архивируются вместе с формулой. Ордеров движок не создаёт.

### AdaptiveLearningEngine

Журнал гипотез со статусами `proposed`, `tested`, `retained`, `archived`. У записи есть формула, окно проверки, метрики и причина архивации. Веса Qwen этот модуль не обновляет. Финальный тестовый отрезок выбирается до перебора гипотез и в выборе следующей формулы не участвует. Сравнение с baseline идёт по средней абсолютной и средней абсолютной процентной ошибке медианы, как в `docs/MODELING.md`.

### QwenResearchAgent

Локальный исследователь. Говорит только с Ollama на `127.0.0.1`. Инструментов сети, ключей биржи и выставления заявок у него нет. Python заранее готовит короткие таблицы: схема полей, уже известные признаки, архив отвергнутых формул. Модель возвращает гипотезу в формате MathematicalEngine. Принять или отклонить её может только Python.

Qwen 3.5 4B в Ollama вызывается тегом `qwen3.5:4b`. На машине 16 GB памяти: в промпт идут короткие сводки. Полное окно контекста 256k для этого контура не используется. Более крупный локальный тег моделью по умолчанию не назначается.

## Phase 2 — подключение Qwen 3.5 4B

Уже сделано в Phase 1.5: непрерывный BTCUSDT Spot 1d с checksum, границы периодов в `wolfai.forecasting.splits`, walk-forward квантильного baseline и случайного блуждания на обучении и валидации. Holdout в метрики не входил. ETH по-прежнему не подключён.

Остаётся:

1. Оставить модель `qwen3.5:4b` на localhost. Веса не дообучать.
2. Зафиксировать грамматику формулы и формат журнала гипотез.
3. Связать внешние ряды с `as_of`.
4. Только после этого замкнуть цикл: Qwen предлагает уравнение, Python его проверяет, журнал хранит результат. Порог сравнения — ошибки из `docs/BASELINE_2019_2024.md`. Holdout для выбора формулы не открывать.
